02MEET YOUR CO-BUILDER

Open the Copilot App

Open your new repository in the Copilot App. This is your workshop: a place to talk about ideas, change the project, and use its terminal.

GitHub is where your project lives. The Copilot App is where you work on it. You don’t need to learn Git to start.

03POWER UP

Install Node.js

On your Windows laptop, download the current Node.js LTS version. Choose the Windows installer and accept its defaults. Node.js runs your project.

Get Node.js LTS ↗

Already had the Copilot App open? Reopen its terminal after installing so it can find Node.js.

04FIRST LAUNCH

Bring your page to life

Run these commands, one at a time, in the Copilot App terminal:

TERMINAL
npm ci
npm run dev

npm ci installs the project’s tools. You only need it the first time, or when those tools change. npm run dev starts your page.

Open the address printed in the terminal, usually http://localhost:5173/. Leave the command running while you build.

05THE FUN PART

Ask Copilot to build a game

Open the Copilot App chat for your repository. Copy this starter prompt and send it. You’re the game designer; Copilot can make the changes in your project.

YOUR GAME BRIEF
Create a complete, fun browser game named Star Catcher in this project.
Edit the files to build it, rather than only explaining how.

Move a basket along the bottom to catch falling stars. Support the left/right
arrow keys and A/D, plus large touchscreen buttons for moving left and right.
Each caught star earns one point. Hitting a falling rock ends the game.
Display the score, an obvious game-over message, and a play-again button.

Keep the existing TypeScript and Vite setup. Add no packages or online services.
Use CSS or simple shapes instead of external images or sounds. Support phones
and laptops, allow browser zoom, use readable colors and text, and make the
buttons work with both keyboard and touch.

Run the project's checks when finished. If missing Google Chrome prevents full
verification, explain that but still let me try the game. Start a local preview
if possible, play-test it, and fix any problems. Explain what changed, the
controls, and whether verification and the preview worked.

No application services to configure. No need to know how to code. Start with this idea, then ask Copilot to make it your own.

06YOU MADE A GAME!

Play. Experiment. Repeat.

Keep npm run dev running and open its printed address in your browser. Microsoft Edge works fine. Catch some stars, dodge the rocks, and try beating your score!

Want a twist? Ask Copilot for a new color scheme, a different challenge, or your own game idea.

Done for now? Press Ctrl+C in the terminal to stop the page. Run npm run dev again next time.

Your next level

Check and build your project

Run npm run verify to check the project, or npm run build to produce publishable files. Full local verification needs Google Chrome, but you can make and play the game without it.

GitHub runs checks on pull requests and pushes to main. Normal checks use Linux; maintainers can manually run Windows verification too. See the template’s Chrome and environment guide.

Maintainer mission: publish and protect your app

Templates copy files, not repository settings. In your new project:

  1. Rename the package with npm pkg set name=your-app and update its lockfile with npm install --package-lock-only. Update the ruleset examples, the path example in vite.config.ts, and the owner in .github/CODEOWNERS.
  2. Adapt the working agreement and documentation to your app. Retain the original MIT copyright notice and add attribution as appropriate.
  3. Enable GitHub Actions. In Settings → Pages → Source, select GitHub Actions. The source README also provides administrator CLI commands.
  4. Push the initial app to main and wait for CI / Verify to pass. If its completion trigger wasn’t present yet, run Deploy manually once. Manual deployment also needs successful push CI for that exact main commit.
  5. Apply and read back the checked-in main ruleset after publication. Its required check is Verify; solo maintainers need no human approval. Review CODEOWNERS and the policy before using them with a team.

Deployment publishes the exact successful main push commit, not a tag or build branch. The workflow token cannot configure Pages or branch rules. A relative Vite base supports different repository names.
